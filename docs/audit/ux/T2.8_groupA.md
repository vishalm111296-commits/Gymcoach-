# T2.8 UX Audit — Group A: Active Workout Session

**Auditor:** Commander (direct evidence pass) · **Date:** 2026-09-09 · **Method:** full source read + computed WCAG contrast from Color.kt tokens
**Scope:** WorkoutSessionScreen.kt (1025 lines), RestTimerOverlay.kt, SetCompleteButton.kt, WorkoutProgressHeader.kt, PreviousPerformanceRow.kt, WorkoutLoggingViewModel.kt (state paths)
**Note:** contrast values computed from token RGB (L1/L2 relative luminance, WCAG 2.x). Where computed < 4.5:1 for small text it is flagged; final on-device confirmation still required per evidence-first policy.

## FINDINGS

- [APP-020] | **P1** | Set logging row | WorkoutSessionScreen.kt:944-990 (SetRow) | touch/readability
  - Observed: 4 OutlinedTextFields with `weight(0.18/0.18/0.13/0.13)` (+42dp chip +56dp checkbox column + spacing) in one row.
  - Expected: weight/reps/RPE/rest fields comfortably editable at 360dp screen width.
  - Impact: on a 360dp phone, fields receive ~32-38dp each — OutlinedTextField content (label + padding ≈ 60dp min) is clipped/cramped; primary logging action becomes error-prone. Likely layout overflow/clipping on ~common small screens.
  - Proposed fix: two-line set row (weight+reps line, RPE+rest line) or icon-labeled compact fields; verify on 320/360dp profiles.
  - Verification: device screenshot at 360dp; contentDescription-free but semantics role needed.

- [APP-021] | **P1** | Set logging | SetCompleteButton.kt:31-34 | contrast/accessibility
  - Observed: containerColor = `SuccessGreen (0xFF4CAF50)`, contentColor = `Color.White`.
  - Expected: ≥4.5:1 (16sp bold text) or ≥3:1 minimum for large text.
  - Impact: computed contrast **2.78:1** — fails even 3:1. "COMPLETE SET" (titleMedium, 16sp bold) is the #1 in-workout action; low-contrast white-on-green strains low-vision users.
  - Proposed fix: darken green container (e.g., #2E7D32 family) or use dark text (#1B5E20) with lighter green bg; keep token-based.
  - Verification: recompute contrast after change ≥4.5:1.

- [APP-022] | **P1** | Session top bar | WorkoutSessionScreen.kt:297-301 | contrast
  - Observed: elapsed timer `bodySmall` colored `colorScheme.primary` (AccentBlue 6C63FF) on DarkBackground.
  - Expected: ≥4.5:1 for 12sp text.
  - Impact: computed **3.21:1** — live duration is a primary orientation cue; low contrast.
  - Proposed fix: use TextPrimary/TextSecondary for the timer, keep AccentBlue only for emphasis accents ≥ title size.
  - Verification: recompute contrast.

- [APP-023] | **P2** | Session bottom bar + dialogs | WorkoutSessionScreen.kt:398-417, 192-194, 279-283 | touch target
  - Observed: "Add Exercise" / "Complete Workout" (bottom row), "Go Back" (completed screen), "Start New Workout" (empty state) use plain `Button` (M3 default min height 40dp) with no height modifier.
  - Expected: ≥48dp interactive height (WCAG 2.5.5 / Material touch guidance).
  - Impact: 40dp targets in the two primary session CTAs; larger row would also reduce miscue between the two adjacent buttons.
  - Proposed fix: `.heightIn(min = 48.dp)` (or 56dp for the pair) on both bottom buttons; consistent across dialogs.

- [APP-024] | **P1** | Set row | WorkoutSessionScreen.kt:915-942 | touch target + accessibility
  - Observed: set-type chip = `Box` 42×24dp, `.clickable { onSetTypeChange(nextType) }`, cycles Normal→Warm→Drop→Fail→Normal.
  - Expected: ≥48×48dp target; announce role/state to TalkBack.
  - Impact: 24dp tap target (smallest interactive element in the app); cycling chip has NO semantics role — TalkBack reads text only, cannot activate, no "cycle to next" hint; a quietly mis-tapped chip mutates set classification.
  - Proposed fix: wrap in 48dp touch target (visual chip can stay 42×24), add `Modifier.semantics { role = Role.Button }` + contentDescription including current+next state.
  - Verification: TalkBack scan; measure hit rect ≥48dp.

- [APP-025] | **P2** | Set row | WorkoutSessionScreen.kt:998-1005 | touch target
  - Observed: `Checkbox(..., modifier = Modifier.size(24.dp))` — forces 24dp visual AND touch bounds.
  - Expected: ≥48dp touch target (Checkbox default pads to 48dp when unconstrained).
  - Impact: small toggle, the completion gesture users hit dozens of times per set.
  - Proposed fix: remove `.size(24.dp)` (keep M3 default 48dp envelope, visual stays ~20dp).
  - Verification: measure hit rect.

- [APP-026] | **P2** | Session navigation | WorkoutSessionScreen.kt:312-319 + GymCoachNavHost.kt:149 | back nav/destructive safety
  - Observed: top-bar back pops the stack unconditionally; no confirmation or "saved" feedback. (Data IS persisted continuously and workout remains ACTIVE/incomplete, resumable from History.)
  - Expected: mid-workout back should inform "Workout saved — resume from History" or offer Finish/Keep-Going.
  - Impact: silent exit → users may believe data was lost; accidental exits strand workout in ACTIVE state.
  - Proposed fix: on back with any logged sets → dialog "Leave workout? Progress saved, you can resume later."; if zero sets → leave silently.
  - Verification: behavior test (navigation + dialog); existing VM resume tests already cover persistence.

- [APP-027] | **P2** | Completion | WorkoutSessionScreen.kt:125-197 | discoverability
  - Observed: after complete → "Workout Complete!" + stats + single "Go Back" button. No "View History" CTA, no auto-pop.
  - Expected: celebrate + offer "View History" (and/or auto-pop to home).
  - Impact: completed session dead-ends; user must navigate manually to see the record.
  - Proposed fix: add "View History" secondary button (nav to WORKOUT_HISTORY) beside "Go Back".
  - Verification: manual flow check.

- [APP-028] | **P3** | Session components | RestTimerOverlay.kt (whole file), PreviousPerformanceRow.kt (whole file) | consistency/dead code
  - Observed: RestTimerOverlay (full-screen ring) is never referenced by WorkoutSessionScreen (inline RestTimerCard used instead); PreviousPerformanceRow is superseded by inline lastPerformance banner.
  - Impact: two parallel timer/perf UX implementations; future edits risk divergence.
  - Proposed fix: delete or wire in; if wired, replace inline card with overlay per design intent.
  - Verification: `rg RestTimerOverlay|PreviousPerformanceRow` usage == 0 after removal or == expected call sites if wired.

- [APP-029] | **P3** | Session screen | WorkoutSessionScreen.kt:374 (`onInstructionsClick = {}`) | dead code
  - Observed: `onInstructionsClick` param is always `{}`; instructions toggle handled by local `showInstructions` state (lines 690-708).
  - Impact: misleading API surface; forces next-dev to guess intent.
  - Proposed fix: drop the parameter (or plumb it).
  - Verification: compile clean.

- [APP-030] | **P1** | Session/history stats | WorkoutSessionScreen.kt:1019-1023 (CompletionStatItem), RestTimerOverlay doc pattern + WorkoutHistoryDetailScreen.kt:457 (SummaryStatItem) | contrast (systemic)
  - Observed: labelSmall text with `color = onPrimaryContainer.copy(alpha = 0.7f)` on primaryContainer (AccentBlueDark).
  - Expected: ≥4.5:1 for 11sp text.
  - Impact: computed **3.78:1** — 11sp labels (Session Summary labels, "Adjust rest:", Summary stat labels) fail AA everywhere the 0.7-alpha pattern is used.
  - Proposed fix: drop alpha to ~0.9 or use a dedicated secondary-on-primary token; audit all `copy(alpha = 0.7f)` on onPrimaryContainer.
  - Verification: recompute each instance ≥4.5:1.
