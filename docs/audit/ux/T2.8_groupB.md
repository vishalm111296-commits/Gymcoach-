## FINDINGS

- [APP-034] | **P1** | Home + Today card | HomeDashboardScreen.kt:122-127,197-202,237-243; TodayWorkoutCard.kt:58-72,107-113 | contrast (systemic)
  - Observed: ALL section eyebrow labels ("READINESS", "COACH", "YOUR FIRST SESSION IS READY", "TODAY'S WORKOUT", "V-SHAPE PRIORITY") are `labelSmall` (11sp) in AccentBlue (6C63FF) on DarkSurface/DarkCard.
  - Expected: ≥4.5:1 for 11sp bold caps text.
  - Impact: computed **3.21:1** on DarkSurface — the app's headline microcopy fails AA across the entire dashboard system.
  - Proposed fix: introduce a lighter "accent-on-dark" variant (e.g., AccentBlueLight 8B83FF → ~4.5:1) for small accent text; keep AccentBlue for buttons/large type.
  - Verification: recompute per instance.

- [APP-035] | **P1** | Home greeting | HomeDashboardScreen.kt:172-177 | contrast
  - Observed: GreetingHeader "GOOD MORNING/..." = `labelMedium` (12sp) in TextTertiary (7A7770).
  - Expected: ≥4.5:1.
  - Impact: computed **3.38:1** — greeting header text fails AA.
  - Proposed fix: use TextSecondary (B8B5AD, ~7.4:1).
  - Verification: recompute.

- [APP-036] | **P2** | Home async states | HomeDashboardScreen.kt:84-100 | loading/empty/error
  - Observed: `when { isLoading -> spinner; todayWorkout == null -> EmptyProgramCard(onViewProgram); else -> TodayWorkoutCard(...) }` — there is NO error branch; a load failure renders "Let's build your plan" CTA.
  - Expected: distinct Error state (retry), Empty state, and Loaded state.
  - Impact: transient DB/query failures mislead users into re-setting-up an existing program.
  - Proposed fix: add `uiState.error` handling with Retry; only show EmptyProgramCard when repository genuinely returns no plan.
  - Verification: unit test for error state rendering (VM state machine).

- [APP-031] | **P2** | Exercise list item | ExerciseItemCard.kt:36 + ExerciseListScreen.kt:135 | spacing/consistency
  - Observed: LazyColumn `contentPadding = PaddingValues(horizontal = 16.dp)` AND each card also `.padding(horizontal = 16.dp, vertical = 8.dp)` → 32dp total horizontal inset; also the STAR/Favorite icon only appears when isFavorite (no toggle affordance).
  - Expected: single 16dp inset aligned to other screens; favorite must be tappable (toggle) or the card non-claiming.
  - Impact: list inset inconsistent with rest of app; favorites are display-only — users cannot favorite from the list.
  - Proposed fix: remove card-level horizontal padding (keep vertical), pass tap-with-trailing-star toggle if favorites are user-settable.
  - Verification: visual diff; behavior if toggle added (new VM method + tests).

- [APP-032] | **P2** | Exercise list | ExerciseListScreen.kt:133-156 | empty state
  - Observed: LazyColumn renders `items(exercises)`; when search/filter yields zero, the body is BLANK — no "No exercises found", no clear-filter CTA.
  - Expected: contextual empty state (search vs filter vs no-data).
  - Impact: user cannot tell if the list failed, filtered nothing, or DB is empty; dead-end with no clear-action.
  - Proposed fix: `if (exercises.isEmpty())` branch with message + "Clear Filters" when filters active.
  - Verification: functional check with search query that matches nothing.

- [APP-033] | **P2** | Exercise list filter sheet | ExerciseListScreen.kt:172-183 | layout overflow
  - Observed: difficulty FilterChips in `Row(fillMaxWidth, spacedBy(8.dp))` with no scroll/wrap — 4+ chips (+ "All") exceed typical width; (equipment row DOES use horizontalScroll, line 191 — asymmetry).
  - Expected: wrap (FlowRow) or horizontal scroll for BOTH rows.
  - Impact: on 360dp devices difficulty chips clip/overflow with no way to reach later options.
  - Proposed fix: FlowRow (androidx.compose.foundation.layout.FlowRow) or match equipment's horizontalScroll.
  - Verification: 360dp screenshot.

- [APP-043] | **P3** | Home summary row | HomeDashboardScreen.kt:254-258 | responsive layout
  - Observed: WeekSummaryRow uses `Arrangement.spacedBy(48.dp)` with two content columns and no weights.
  - Expected: graceful fit at 320-360dp widths.
  - Impact: "workouts this week"/"personal records" columns can crowd/overflow on smallest phones.
  - Proposed fix: weight-based columns or smaller spacing; wrap to two rows if needed.
  - Verification: 320dp screenshot.
