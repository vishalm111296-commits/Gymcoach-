### APP-039 | severity: P0 | screen: WorkoutHistoryScreen | file: WorkoutHistoryScreen.kt:92-102 | dimension(s): accessibility, hierarchy
**Observed:** `IconButton` for back navigation (line 92-98) has `contentDescription = "Back"` — correct. However, `IconButton` for "New Workout" (lines 99-102) has `contentDescription = "New Workout"` — correct. BUT the filter tabs (lines 126-143) use `Tab` with `text = { Text(filter.name.replace("_", " ")) }` — no explicit `contentDescription`. Material3 `Tab` uses text for semantics, but selected state is not announced.

**Expected:** Tabs should expose selected state via semantics. Material3 `Tab` handles this when `selected` prop is set — but verify talkback announces "Tab, selected" vs "Tab, unselected".

**Impact:** Screen reader users may not know which filter is active.

**Proposed fix:** Verify with TalkBack. If selected state not announced, add `contentDescription = "${filter.name.replace("_", " ")} tab, ${if (filterOption == filter) "selected" else "unselected"}"` to `Tab`.

### APP-040 | severity: P0 | screen: WorkoutHistoryScreen | file: WorkoutHistoryScreen.kt:146-164 | dimension(s): accessibility, touch targets
**Observed:** Sort dropdown `IconButton` (line 147-149) has `contentDescription = "Sort"` and `Icon` size 24dp default. No `Modifier.size(48.dp)` — touch target likely 24dp. `DropdownMenuItem` text items (lines 154-161) use default sizing.

**Expected:** All interactive targets ≥48dp. `IconButton` should have explicit size. Dropdown items should have sufficient padding.

**Impact:** Small touch target for sort icon; dropdown items may be too small.

**Proposed fix:** Add `modifier = Modifier.size(48.dp)` to sort `IconButton`. Ensure `DropdownMenuItem` has `Modifier.padding(horizontal = 16.dp, vertical = 12.dp)` minimum.

### APP-041 | severity: P0 | screen: WorkoutHistoryScreen | file: WorkoutHistoryScreen.kt:252-268 | dimension(s): destructive safety, accessibility
**Observed:** Delete confirmation `AlertDialog` (lines 253-268) has confirm button "Delete" in error color (good), dismiss "Cancel". But: **no workout name in confirmation text** — just "Are you sure you want to delete this workout?". User cannot verify which workout they're deleting.

**Expected:** Confirmation should include workout identifier: "Delete \"Workout Name\" from history?" or show date.

**Impact:** Accidental deletion of wrong workout — no undo (deleted immediately from DB via `viewModel.confirmDelete()`).

**Proposed fix:** Pass `deleteTarget` workout name/date to dialog. Update dialog text: `text = { Text("Are you sure you want to delete \"${workout.notes.ifBlank { \"Workout ${workout.id}\" }}\"? This cannot be undone.") }`.

### APP-042 | severity: P1 | screen: WorkoutHistoryScreen | file: WorkoutHistoryScreen.kt:113-123 | dimension(s): touch targets, discoverability, accessibility
**Observed:** Search `OutlinedTextField` (lines 113-123) has `leadingIcon = { Icon(Icons.Default.Search, contentDescription = "Search") }` — good. But **no clear button** when query is non-empty. User must backspace entire query.

**Expected:** Search field should show trailing clear icon (`Icons.Default.Close`) when `searchQuery.isNotBlank()`, with `contentDescription = "Clear search"`.

**Impact:** Poor discoverability to clear search; extra taps needed.

### APP-043 | severity: P1 | screen: WorkoutHistoryScreen | file: WorkoutHistoryScreen.kt:221-248 | dimension(s): touch targets, hierarchy, accessibility
**Observed:** Date range picker dialog (lines 221-248) uses `DatePickerDialog` + `DateRangePicker`. `confirmButton` and `dismissButton` are `TextButton` — default height ~40dp, below 48dp. `DateRangePicker` has `Modifier.fillMaxWidth().height(400.dp)` — fixed height, may overflow on small screens.

**Expected:** Dialog buttons ≥48dp height. Picker should use `Modifier.fillMaxSize()` or constrain to available space.

**Impact:** Hard to tap OK/Cancel on small screens. Picker may be clipped.

**Proposed fix:** Wrap buttons in `Button` with `.heightIn(min = 48.dp)`. Use `Modifier.fillMaxSize().heightIn(max = 400.dp)` for picker.

### APP-045 | severity: P1 | screen: WorkoutHistoryDetailScreen | file: WorkoutHistoryDetailScreen.kt:182-203 | dimension(s): loading/empty/error, accessibility
**Observed:** Loading state (lines 183-190) shows `CircularProgressIndicator()` centered — no text label. Error state (lines 192-203) shows error text in `bodyLarge` with `error` color — good contrast. **No retry action** in error state.

**Expected:** Loading should announce "Loading workout details" via semantics or `contentDescription`. Error should offer "Retry" button.

Error: Add `Button(onClick = { viewModel.loadWorkout(workoutId) }) { Text("Retry") }` alongside error text.

### APP-049 | severity: P2 | screen: WorkoutHistoryDetailScreen | file: WorkoutHistoryDetailScreen.kt:462-509 | dimension(s): contrast, readability, hierarchy
**Observed:** `MuscleGroupRow` (lines 462-509) uses `Card` with `containerColor = surfaceVariant` (#1F2B45), text colors: muscleName = `bodyMedium` on `onSurfaceVariant` (TextSecondary #B8B5AD), volume = `primary` (AccentBlue #6C63FF). Contrast: TextSecondary on DarkSurfaceVariant ≈ 3.8:1 (passes AA for large text, borderline for bodyMedium). AccentBlue on DarkSurfaceVariant ≈ 3.2:1 — **fails WCAG AA for non-text (3:1 minimum for UI components, 4.5:1 for text)**.

**Expected:** Volume text (primary color on surfaceVariant) should meet 4.5:1. Needs visual check.

**Impact:** Volume numbers may be hard to read for low-vision users.

**Proposed fix:** Use `onSurfaceVariant` for volume with `fontWeight = SemiBold`, or lighten `surfaceVariant` for this card. Verify with contrast tool.

### APP-051 | severity: P2 | screen: BottomNavigation | file: BottomNavigation.kt:41-68 | dimension(s): touch targets, accessibility, consistency
**Observed:** `GymCoachBottomNav` (lines 42-68) — `IconButton` with `Modifier.size(48.dp)` (line 58) — **GOOD, meets 48dp**. Active tab tint = `AccentBlue`, inactive = `TextTertiary`. `contentDescription = item.label` on Icon — good. **Missing**: selected state semantics (no `selected` prop on IconButton, no indicator for TalkBack). No label text — icon-only nav.

**Expected:** Icon-only bottom nav should expose selected state via semantics. Material3 `NavigationBarItem` would handle this; custom implementation needs `semantics { selected = active; role = Role.Tab }`.

**Impact:** Screen reader users don't know which tab is active.

**Proposed fix:** Wrap `IconButton` in `Box` with `modifier = Modifier.semantics { selected = active; role = Role.Tab; contentDescription = "${item.label}${if (active) " selected" else ""}" }`. Or migrate to `NavigationBar`/`NavigationBarItem` (Material3).

### APP-052 | severity: P2 | screen: Theme/Color/Type (Shell) | file: Color.kt, Type.kt, Theme.kt | dimension(s): consistency, spacing, typography
**Observed:** Theme tokens: **No spacing scale** (no `Spacing` object with 4/8/12/16/24/32dp tokens). **No shape scale** (no `Shape` object with small/medium/large rounded corners). **No elevation scale** (no `Elevation` object). Hardcoded dp values throughout: `16.dp` padding (ubiquitous), `12.dp` spacing, `8.dp`, `4.dp`, `56.dp` nav height, `48.dp` icon buttons, `400.dp` picker, `24.dp` icons. Type: Material3 typography defined but **no text scaling support** (no `LocalTextScaleFactor` usage or `fontSize = 16.sp` that respects user font size).

**Expected:** Design system should expose spacing/shape/elevation tokens. Text should scale with system font size (sp units already used — good, but verify no hardcoded `dp` for text).

**Impact:** Inconsistent spacing across screens. No centralized theming for spacing/shape/elevation. Users with large font size may get clipped text.

**Proposed fix:** Create `Spacing.kt` with `val xs = 4.dp, sm = 8.dp, md = 16.dp, lg = 24.dp, xl = 32.dp`. `Shape.kt` with `val small = RoundedCornerShape(4.dp), medium = RoundedCornerShape(12.dp), large = RoundedCornerShape(28.dp)`. `Elevation.kt` with `val card = 4.dp, modal = 8.dp`. Replace hardcoded dp with tokens. Verify all text uses `sp`.

### APP-054 | severity: P2 | screen: WorkoutHistoryScreen | file: WorkoutHistoryScreen.kt:22-24, 126-128 | dimension(s): performance, offline
**Observed:** `ScrollableTabRow` (line 126) recomposes on every filter change. Filter options are enum values — stable. But `Tab` composables recreate on each recomposition. `LazyColumn` items use `key = { it.id }` (line 210) — good for list stability. **No pagination** — loads all workouts into memory. For large history, this could cause jank.

**Expected:** Consider pagination or `LazyColumn` with `itemsIndexed` and windowing. Filter tabs are fine (only 4 options).

**Impact:** Potential memory/performance issue with 100+ workouts.

**Proposed fix:** Add pagination to ViewModel (load 20 at a time, append on scroll). Or use `Pager` with `LazyColumn` windowing.

### APP-055 | severity: P2 | screen: WorkoutHistoryDetailScreen | file: WorkoutHistoryDetailScreen.kt:423-442 | dimension(s): contrast, hierarchy, readability
**Observed:** `WorkoutSummaryCard` (lines 393-442) uses `containerColor = primaryContainer` (AccentBlueDark #4A42E0), text = `onPrimaryContainer` (TextPrimary #F5F5F0). Contrast: TextPrimary on AccentBlueDark ≈ 5.2:1 — **passes AA for all text sizes**. Good. But `SummaryStatItem` uses `onPrimaryContainer.copy(alpha = 0.7f)` for labels — 5.2 * 0.7 ≈ 3.6:1 — **fails AA for body text (needs 4.5:1)**.

**Expected:** Stat labels at 70% opacity may not meet contrast.

**Impact:** "Duration", "Exercises" labels harder to read.

**Proposed fix:** Use `onPrimaryContainer` at full opacity for labels, or `copy(alpha = 0.85f)` minimum. Differentiate via `fontWeight` or `fontSize` instead of opacity.
