# P0 Verification Evidence — REVISED after schema-lineage reconciliation

**Date:** 2026-08-23 · **Branch:** `p0/stabilization` · **Gate PR:** #12
Directive-mandated record of library/API decisions made during P0, with their
verification status. This revision supersedes the earlier version of this
document, whose claims were written before the dual-lineage problem was
discovered and several of which were no longer true.

## Room migrations (v7 → v8 — corrected from v6 → v7)

- **History correction:** this branch originally carried a SECOND, incompatible
  v7 lineage (own `MIGRATION_6_7`, camelCase junction DDL, `exportSchema=false`)
  that could never merge into main and silently skipped Room schema validation.
  It has been removed. Main's canonical lineage (FTS4 external-content search
  at v7) is restored verbatim; the workout lifecycle lands as append-only
  **`MIGRATION_7_8`**: `ALTER TABLE workouts ADD COLUMN status TEXT NOT NULL
  DEFAULT 'NOT_STARTED'` plus three UPDATE backfills, registered in
  `addMigrations(...)`. No `fallbackToDestructiveMigration()` anywhere.
- **Contract:** entity column carries `@ColumnInfo(defaultValue = "NOT_STARTED")`;
  the DDL default string must equal the annotation default exactly or upgrade
  throws `IllegalStateException`. The strings are identical by construction and
  review, but the equality MUST still be proven by an instrumented
  `MigrationTestHelper` test. Schema export is now enabled
  (`room.schemaLocation`), so `8.json` onward is generated by normal builds;
  a v7 JSON for the helper requires one instrumented build of main's v7 tree.
  CI runs JVM-only (`testDebugUnitTest`) - execution needs an emulator run.
- **Backfill truth table:** completed=1 → COMPLETED · completed=0 ∧ has
  exercises → ACTIVE · completed=0 ∧ empty → ABANDONED.
- **Post-migration hygiene:** `WorkoutDao.abandonEmptyActiveWorkouts()` reaps
  contentless ACTIVE rows to ABANDONED on every resume lookup (skeptic-review
  residual), so force-quit strays cannot linger as live-state artifacts.

## Compose layout

- Progress dashboard uses one scrollable `Column` with plain rows. The
  historical nested-lazy-container crash is structurally impossible in the
  current tree - no lazy container sits inside the vertical-scroll Column.

## Duplicate ViewModel fix

PR #6 added `ProgressViewModel.kt` while `ProgressDashboardScreen.kt` still
declared its own `ProgressViewModel`/`ProgressUiState` in the same package -
a duplicate-class compile failure that latent-red CI never surfaced. The stale
copy is removed; the screen binds the shared superset UiState.

## VolumeCalculator compile fix

`calculateWeeklyVolume` declared `List<WorkoutSetEntity>` but read
`date`/`exerciseId` properties that entity does not have - the file could not
compile. Input replaced with a neutral `CompletedSetEntry` record (no
production callers yet). Trained-weeks-only averaging semantics are pinned as
a documented honesty contract in its KDoc and tests.

## State machine

Explicit enum persisted as TEXT (`workouts.status`). PAUSED exists in the
domain model but rest-timer pause remains in-memory session state
(RestTimerManager); persisting PAUSED adds schema churn without user value
today. Legacy Boolean `completed` stays in lockstep (COMPLETED == true)
because all analytics queries filter on it; drift risk flagged for a future
P1 refactor of analytics predicates onto status.

## Discard workflow (complete)

`Discard` button wired into `WorkoutSessionScreen`: explicit action,
confirmation dialog with content-dependent honest wording (empty → permanent
delete; content → ABANDONED, never resurfaces as Resume), persistence via a
VM-independent `CoroutineScope(SupervisorJob() + Dispatchers.IO)` so
same-frame navigation cannot cancel the write. Process-death mid-write falls
back safely: the row stays ACTIVE + contentful and remains resumable.

## Honesty contracts as executable tests

Live-corpus contract now targets the JSON assets the seeder actually ships
(`AssetCorpusContractTest`): global name/id uniqueness, equipment whitelist
{dumbbell, bench, bodyweight}, taxonomy resolution, substitution-graph
integrity, presses-never-claim-lat rule, machine-parseable rep ranges. The
exact corpus count is printed to the CI log rather than hardcoded (previous
tests validated dead-code Kotlin seed objects under `core.data.seed`, which
do not ship). Engine suites cover evidence bands, Epley e1RM cap, PR gates,
double-progression tiers, deload rule, warmup/incomplete filtering.
Calorie fabrication REMOVED from Progress (volume×0.05) → real Volume/Set;
"Weekly Workouts" relabeled honestly "Weeks Tracked"; literal `0.0%%`
zero-trend artifact fixed.
